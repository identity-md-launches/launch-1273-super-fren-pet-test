# SFPT website validation

## Scope and decisions

Complete for the stated website scope. Source is `site/`, with a byte-for-byte runtime export in `dist/`. Home, docs and 404 pages were reviewed. The existing Solidity implementation, tests, launch manifest, dependencies, build configuration and ignore files were preserved.

The full JSON brief was retrieved with curl from `https://www.si-md.xyz/api/chat?op=site-brief&label=superfrenpettest`; the web-reading tool could not open it. The supplied 400×400 logo was downloaded locally. The live feed is not deployed in this workspace, so browser tests used explicitly empty or controlled fixtures through the local preview/test server. No fixture token address or fabricated market value is shipped in `site/` or `dist/`.

The authoritative name is Super Fren Pet Test / SFPT. The creator's SFP room, bridge, FP conversion and staking wishes are represented as clearly labeled concept scenery. No completed audit or explorer verification is claimed without evidence. The notice “Do not buy, this is a test” is visible in the hero and repeated in the guide, docs and share texts. The calculator models gross SFPT output and integer tax, not invented dollar revenue or returns.

## Browser and interaction evidence

The production export was served under `/preview/`, with a same-origin empty launch-data fixture. Chromium automation checked home, docs and 404 at widths 320, 360, 375, 390, 768, 1024, 1440 and 1920px. All had one H1, no document overflow and no broken images. Axe WCAG A/AA scans at 375 and 1440px reported zero violations on all three pages. This is automated coverage, not a claim of complete accessibility compliance.

The supplied browser tool was also used to inspect rendered screenshots of the desktop hero and full homepage, 390px first screen, mobile docs header and 404 page. Final selected evidence is `artifacts/site-desktop.jpg` (1440×900) and `artifacts/site-mobile.jpg` (390×844). The visible primary Docs action ends around y=474 on the mobile screenshot. Full-page and focused-control screenshots plus machine-readable results are regenerated by the verification workflow under `test/scratch/site-validation/`; scratch files are intentionally not submitted. A compact results copy is retained in the review artifacts.

Meaningful interaction checks covered:

- Mobile menu open/close, anchor selection, Escape and focus restoration; native keyboard FAQ and range control.
- Exact 1,000 and 1,000,000 SFPT examples, 18-decimal rounding at 49/50 minor units, zero, supply ceiling, invalid-input recovery and conservation.
- All buying-guide steps and Next cycling, the pet-room buy trace, animation pause/resume, initial and changed reduced-motion preferences, and a forced no-WebGL fallback.
- Copy-link and contract clipboard contents, three distinct X intents and opening a share destination in a new tab (intercepted locally).
- Valid feed data, valid numeric zero, dynamic logo precedence, pending fields, invalid JSON, cached-link labels, invalid addresses and executable URL rejection.
- The 30-second data interval advanced with Playwright virtual time. No real-time 30-second wait was required.

The initial timer and motion assertions exposed asynchronous test-harness races: a request event precedes its route callback, and a media change precedes the listener update. Tests now wait for the response and disabled-state transition. The final run passed.

## Packaging review

The complete candidate Git file set is below the 8,388,608-byte limit even as uncompressed file contents (approximately 8.29 MB). Independently compressing each candidate file with zlib gives approximately 5.90 MB, before Git's identical-blob deduplication. This is a conservative file-content check, not a claim to have created or modified a Git bundle. Browser-generated `.playwright-mcp/` output was removed. No cache/dependency directory, source map, npm archive or gitlink occurs in the candidate set. Existing ignore rules were not edited. `dist/` is included; named evidence in the existing ignored `artifacts/` directory is retained for the assignment's artifact delivery. Exact counts are in `artifacts/submission-budget.json`.

## Remaining limitations

- Ethereum mainnet deployment, explorer verification, production `/simd-coin.json`, real launchpad destinations and market data were not verified. There is no deployment key, guessed token address or live transaction in this work.
- The inherited integration suite uses the real PoolManager locally, but no live mainnet fork or protected external launch harness was available. No new Solidity behavior was introduced.
- Browser coverage is Chromium emulation. Firefox, Safari, physical devices, screen readers and native 200% zoom remain unperformed. Local font loading and ordinary keyboard behavior were checked.
- The browser tool emitted software-WebGL `ReadPixels` performance warnings during screenshots, with zero baseline application errors. Those warnings are not a measured hardware-performance failure.
- The static social meta uses the required supplied logo. The runtime logo field updates images and metadata in JavaScript; crawlers that do not execute JavaScript will continue to see the bundled fallback until the HTML is republished.
- Hosting must provide `/simd-coin.json` and serve the custom 404 at its own URL so its relative assets resolve. The exported site itself needs no backend or build system.
